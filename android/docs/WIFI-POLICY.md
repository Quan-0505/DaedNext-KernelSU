# Wi-Fi 黑白名单自动切换

这项功能根据手机当前实际使用的网络与 Wi-Fi SSID，决定是否启用手机的透明代理。它不检测路由器是否提供代理，名单由用户维护。

## 模式

| 模式 | 名单内 Wi-Fi | 名单外 Wi-Fi |
| --- | --- | --- |
| 黑名单 | 手机直连，交由 Wi-Fi 上游处理 | 使用 DaeNext 原有规则和节点 |
| 白名单 | 使用 DaeNext 原有规则和节点 | 手机直连 |

“非 Wi-Fi 网络使用代理”独立控制移动数据等网络，默认开启。关闭整个 Wi-Fi 自动切换功能后，恢复原有 DaeNext 行为。新安装默认不启用自动切换，也不预置任何个人 SSID。

## 设置

打开 KernelSU 的 DaeNext 模块 WebUI，在“Wi-Fi 自动切换”中启用功能、选择模式，按每行一个名称填写 SSID 并保存。黑白名单分别保存；切换模式不会清除另一份名单。“添加当前 Wi-Fi”只填写名单，点击保存后才生效。

SSID 精确匹配、区分大小写，支持中文、空格和引号。不要在名称外额外加引号。每个 SSID 限制为 1～32 个 UTF-8 字节，每份名单最多 128 项。不要把没有上游代理的 Wi-Fi 加入直连名单，否则该网络下的海外访问需要上游自身提供可达性。

## 运行行为

- 只在当前实际出口为 Wi-Fi 时使用 SSID 名单；连接着 Wi-Fi 但系统实际使用移动数据时，执行非 Wi-Fi 策略。
- 命中直连策略后，保留 daemon 和本地管理面板，释放 DaeNext 自己的数据面绑定、监听及拓扑。节点、订阅、DNS、分流配置与选中状态保持不变。
- 离开直连网络后，只有用户原来启用了内核，才自动恢复；手动停止后不会因为下一次网络切换被重新拉起。
- 在直连策略期间通过管理面板启动或应用配置，会保存启用意图；数据面等待网络策略允许后恢复。
- 连续两次观察一致后应用网络变化，减少切换时旧 SSID 和新路由混用。无法读取 SSID 或暂时没有可用路由时，不根据空名称新增直连判断，保留使用代理的目标。
- 已启用的 Google 联网兼容在策略直连期间仍维护对应应用的联网权限；手动停止内核或整个服务后还原原策略。

切网、释放或重建数据面时，已有连接可能中断并需要应用重连。自动切换仍依赖当前网络以及代理节点的可达性。

## 数据与维护

个人设置保存在 `/data/adb/daenext/wifi-policy.json`，权限 0600，升级和卸载保留，模块备份包含该文件。运行期观察结果在 `run/` 下，服务启动时重新读取网络，不把上次 SSID 当成当前网络。

```sh
CTL=/data/adb/modules/daenext/bin/daenextctl
"$CTL" wifi-policy get
"$CTL" status
```

机器接口 `wifi-policy set BASE64_JSON` 用 UTF-8 JSON 的标准 Base64 编码传输设置，避免将 SSID 拼接为 Shell 代码。设置对象字段为 `enabled`、`mode`、`blacklist`、`whitelist`、`proxy_on_non_wifi`。请通过 WebUI 修改，不要上传包含个人 Wi-Fi 名称的配置或日志。

交互语义参考 [NetProxy](https://github.com/Fanju6/NetProxy-Magisk)，配置与生命周期由本模块独立实现，不依赖 NetProxy 运行。
