# Android 实测记录

## alpha6 — 2026-10-27

设备沿用下方一加 13 / Android 17 环境，核心 `3.1.0-android-ksu.5`。本轮针对 Wi-Fi 自动切换，使用带上游代理的 Wi-Fi 验证手机数据面旁路，并切换蜂窝网络验证恢复。

| 检查 | 结果 |
| --- | --- |
| 源码回归 | daemon 单线程完整回归 664 通过、1 项原有跳过；product-runtime 40 通过；product-control 本地控制测试 1 通过。WebUI 测试覆盖黑白名单独立保存、中文及特殊字符传输、添加当前 Wi-Fi 与旁路显示。 |
| 黑名单与切网 | 两轮 Wi-Fi → 5G → Wi-Fi 均自动切换；Wi-Fi 下释放 `dae0`、`runtimeRunning=false`、`networkPolicyPaused=true`，5G 下自动重建数据面并恢复运行。切换全程 daemon PID 不变。 |
| 实际连接 | 上述两轮分别通过严格 TLS 的 Google 204、YouTube 200、Telegram Web 200 检查。测试针对 HTTP/TLS 连接，不等同于逐项验收 App 的所有功能。 |
| 白名单 | 同一 Wi-Fi 加入白名单后接管，移出后释放；两种状态均通过上述连接检查。测试后恢复原黑名单模式。 |
| 用户启停意图 | 直连期间手动停止后，切到 5G 仍保持停止；直连期间重新启动只记录启用意图，离开后恢复数据面。该路径完成两次测试。 |
| 服务生命周期 | 策略直连期间连续两次停止／启动服务，停止约 1.2～2.3 秒，启动后保持直连且管理面板可用；后续一致性备份恢复服务正常。 |
| 数据与备份 | 包含 SQLite WAL 的升级前后快照对比：账户、节点、订阅内容、策略组与绑定、配置、DNS、路由均一致；订阅刷新时间更新。Wi-Fi 设置与迁移配置一致，并已纳入模块备份。 |
| 安装 | KernelSU 标准安装成功；活动目录及重启待应用目录的运行文件按清单校验，个人名单仅写入持久化数据目录，发布包默认关闭且名单为空。 |

手动停止／重新启动后的一个蜂窝样本中，Google 解析超时、YouTube 解析失败，而 Telegram Web 可用；重新切换后的两次检查及重复原操作路径的两次检查均恢复正常，未复现持续失联。本轮未定位该单次解析异常的根因，不将它记为已修复。模块就绪仅表示生命周期状态，不能替代实际 DNS 与连接检查。

本轮未重新执行手机冷启动，也未覆盖所有 UDP/QUIC 或 IPv6 场景；下方历史验证不能替代 alpha6 的同场景验收。原始日志、数据库与个人 SSID 名单仅保存在私有验证目录。

## alpha5 — 2026-10-27

设备及系统沿用下方 alpha4 环境。先在有上游代理的 Wi-Fi 完成重复切换，再使用无上游代理的手机热点补测 Wi-Fi → 5G → Wi-Fi；两种网络环境均按实际出口验证。核心 `3.1.0-android-ksu.4`，节点健康检查间隔 50 秒。

| 项目 | 结果 |
| --- | --- |
| Rust 回归 | 恢复相关 45 项、接口监测 39 项全部通过；覆盖相同配置强制重绑、保留产品版本、启动恢复避让、旧出口健康缓存失效及双协议栈路由探测。 |
| 网络切换 | 连续 3 轮 Wi-Fi ↔ 5G 均自动恢复；6 次切换中核心进程 PID 不变，每次只重建一次，未出现启动恢复重复介入。 |
| 无上游代理 Wi-Fi | 普通手机热点连接正常；热点→5G 约 7.3 秒自动恢复，回连同一热点后再次通过严格 TLS 检查；全程核心 PID 不变。回连误选其他 Wi-Fi 的一次样本已排除。 |
| 真实联网检查 | 每轮严格 TLS 检查 Google 204、YouTube 200、Telegram Web 200。Wi-Fi→5G 本次 3 个样本从切换到接口和可用节点就绪约 5.6～7.4 秒；Wi-Fi 方向约 12.4～13.8 秒。 |
| 配置不变的接口变化 | 调整并还原 Wi-Fi MTU，数据面自动重新绑定；测试后恢复原 MTU。 |
| 正式安装及数据 | KernelSU 安装成功，活动目录及重启待应用目录的 127 个运行文件校验通过。包含 WAL 的 SQLite 备份对比确认账户、订阅、节点、策略组及绑定数据未改变；按用户要求将原检查间隔改为 50 秒。 |
| 附加检查 | 国内直连 HTTPS 200；携带 Android INET 组的 Play UID 请求返回 302、Google 服务 UID 返回 204，TLS 校验均为 0。独立 IPv6 Google HTTPS 请求超时，本轮未通过 IPv6 端到端验证。 |
| 稳定性短测 | 最后一轮切换后连续观察，重载计数保持不变。用户反馈实际应用正常有网。 |

alpha5 此轮未重新执行冷启动；下方 alpha4 冷启动结论不代表 alpha5 已完成相同验证。切换中连接可能中断，恢复还受节点探测及网络条件影响；上述时间为本设备本次样本，不是所有网络的恢复时限。原始运行日志及数据库只保留在私有验证目录。
