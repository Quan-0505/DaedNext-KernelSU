# 首次导入节点后无法启动

适用于错误中包含 `no user-defined routing outbound with a resolvable node link was found` 的情况。它表示运行配置没有找到可用的用户代理出口，不是设备型号或 AnyTLS 握手失败的结论；不要按错误末尾的通用提示随意修改环境变量。

安装包的默认路由为直连，添加节点不会自动修改用户路由。需要建立“节点 → 群组 → 路由”的关联。

## 使用 App 配置

1. 打开 **资源 → 群组 → proxy → 管理成员 → 添加节点**，选择已导入的节点。使用订阅时改为关联订阅，并检查筛选后的候选节点数。
2. 单节点可以使用固定策略；固定策略只允许一个候选。多个节点请选择合适的自动优选策略。
3. 打开 **资源 → 路由**，编辑已选方案的 **兜底行为 → 设置兜底**，将流量出口选择为 `proxy` 并保存。已有分流方案可按需要添加指向群组的规则，无须将全部流量设为代理。
4. 打开 **资源 → 配置 → 应用当前配置**，再检查运行状态与实际海外应用。

高级面板同样需要先在群组中关联节点，再让当前路由引用该群组。简单路由示例：

```dae
routing {
  dip(geoip:private) -> direct
  fallback: proxy
}
```

上述示例保留私网直连，其余流量进入 `proxy`，并非国内外分流模板。不要覆盖已有复杂路由；修改前备份，编辑保存后须应用配置。

若完成关联后出现新的证书、解析或握手错误，应按新错误检查节点参数与网络。不要关闭 TLS 校验来处理本页所述的配置关联问题，也不要公开节点完整链接、订阅地址或数据库。
