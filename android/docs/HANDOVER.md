# Android 网络切换恢复

Wi-Fi 与蜂窝网络会使用不同的策略路由表。`wan_interface: auto` 的配置文本不变，但接口、地址、默认路由和 eBPF 绑定可能已经变化。

## alpha5 修复

- 已就绪的接口恢复请求强制执行 `KernelRebind`，不再被普通配置比较降为 `NoChange`。
- 重新准备核心时保留当前已提交的 routing/geodata 版本，避免随后恢复已保存配置时再次重建。
- 启动恢复检查运行状态以及 apply/cleanup 状态，避免把正常重建期间暂时为空的运行槽当成启动失败。
- 切网重建不继承旧出口的节点存活和延迟缓存；新运行环境立即执行启动探测，普通配置重载仍保留健康缓存。
- 新安装默认检查间隔为 50 秒；升级不会覆盖已有用户的间隔设置。周期检查影响故障发现时机，不改变 TLS 握手自身的速度。
- 启动与运行期均使用 Android 实际策略路由，监测 IPv4 和 IPv6 的全部有效出口；忽略 `lo`、`dummy0` 占位接口。

切网期间旧连接可能中断，应用需要重连。正常恢复会重建数据面，不需要用户手动开关内核；模块进程和面板可继续运行。恢复仍依赖实际网络及节点可用，不保证切换瞬间零丢包。

## 验证方法

1. 保留 daemon PID、物理 runtimeGeneration、reloadCount、lastReport/source 和实时 residentInterfaceState。
2. 重复 Wi-Fi → 蜂窝和蜂窝 → Wi-Fi，记录实际策略路由、绑定接口和恢复原因。
3. 验证代理 HTTPS、国内直连、证书校验，以及服务停止时 Google 联网策略还原。
4. 对同一出口的 MTU/接口状态变化单独测试，确认配置未变化时也会真正重新绑定。
5. 检查稳定期间计数不持续增长，启动恢复不在每次切换后重复重建。

原始日志、运行时 JSON 和数据库只留在私有验证目录。公开结果见 [VALIDATION.md](VALIDATION.md)。
