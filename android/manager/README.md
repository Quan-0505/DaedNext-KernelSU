# DaedNext Android Manager

原生 Android 管理器，与 DaedNext KernelSU 模块共同工作。交互分工参考 [NetProxy Android Manager](https://github.com/Fanju6/NetProxy-Magisk/tree/main/src/android)，客户端与模块接口独立实现，未复制其 UI 或业务源码。

当前源码版本 **0.1.12**。桌面使用 C 版卡通叼刀鹅自适应图标，支持圆形、圆角方形及 Android 13 主题图标。首页采用选定的 B 版琉璃鹅核，代理启停使用有限时长的原生聚散／点亮动画。底部「资源」进入六宫格工作台，统一管理配置、DNS、路由、群组、节点和订阅；六项均为原生页面，使用统一图标、分类色、卡片和明暗主题。资源数量来自本机 API，节点数包含独立及订阅节点。支持「设置 → 外观」：跟随系统、浅色 · 云雾、深色 · 星夜。浅色使用暖灰白背景、近白卡片与墨紫主按钮；深色延续星夜风格。视觉参考 [Opal](https://opalapp.com/)，图形独立绘制，不包含 Opal 的图片、商标或字体；维护规范见 [DESIGN.md](DESIGN.md)。alpha8 ZIP 内包含 Manager 0.1.7；历史 alpha7 ZIP 内为 Manager 0.1.1。

## 安装

需要 Android 8.0 或更新版本、Root 授权，以及本项目 alpha7 或更新模块。

1. 在支持的 Root 管理器中安装 ARM64 模块 ZIP，按管理器提示重启。
2. 安装同一 Release 的独立 APK，或从 ZIP 解压 `manager/DaedNext-Manager.apk` 安装。
3. 在当前 Root 管理器的超级用户列表中允许 **DaedNext**，再打开 App。
4. 已有账户、节点、订阅及 Wi-Fi 策略直接使用。首次安装没有账户时，进入高级面板完成账户和基础配置。

App 不附带代理核心，不能脱离模块提供代理。安装或卸载 App 不会删除模块中的配置。

## 功能

| 页面 | 操作 |
| --- | --- |
| 仪表盘 | 代理启用／暂停、当前 Wi-Fi 策略、进程状态、实时上传／下载速度、CPU 占用和内存占用。 |
| 资源 | 配置、DNS、路由、群组、节点、订阅六宫格，显示本机实际数量。 |
| 节点 | 独立及订阅节点列表、延迟记录、单节点测速、链接导入、名称与链接编辑、删除。 |
| 订阅 | 添加、编辑、更新、删除及自动更新状态。地址默认掩码显示。 |
| 网络 | Wi-Fi 黑白名单分别编辑、添加当前 Wi-Fi、独立的非 Wi-Fi 代理选项。 |
| 设置 | 外观、后台服务启停、开机启动、Google 联网兼容、一致性备份、日志。 |
| 配置 | 原生配置列表、新建／复制、编辑探测与拨号等参数、选择、删除和单独应用。端口与路由标记沿用模块值。 |
| 群组 | 原生群组列表、策略编辑、新建／删除、节点添加／移出、订阅关联／移出与正则名称筛选。 |
| DNS | 方案新建／复制／重命名／选择／删除，上游增改和移除，查询／响应规则、规则顺序与兜底行为。 |
| 路由 | 方案管理，原生条件与出口编辑、条件模板、规则上移／下移／删除、兜底行为。 |
| 高级面板 | 现有 DaedNext 面板作为附加工具；六项资源不依赖 WebView。 |

“暂停代理”记录用户停用意图，保留后台管理服务；“停止服务”关闭整个模块服务。Wi-Fi 策略直连期间启用代理只记录启用意图，待离开直连网络后恢复接管。

配置和群组保存后不会自动重载运行时；需要时在配置页点击「应用当前配置」。编辑配置和群组策略时会先检查版本，发现其他页面已修改则保留表单并提示刷新；这属于客户端检查，服务端并未为这些更新提供原子的版本条件写入。节点和订阅按单个关联增删，保留其他成员及其筛选条件。

DNS 和路由同样分开保存与应用。保存时将候选段落放入本机生成配置，通过只读预览接口校验，再检查资源版本并更新单个方案；不调用完整配置导入接口。结构化编辑按原文片段修改，保留其他段落；移动规则时关联注释随规则移动。复杂或暂不支持结构化展示的语法仍保留，并可在原生「完整文本」编辑器中处理。新增响应区块时自动补上必需的 `fallback: accept`，已有兜底保持不变。

当前核心若无法生成用于预览的配置，DNS／路由编辑会显示错误并保留草稿，不绕过校验写入。原生客户端的版本检查不能替代服务端原子条件写入，请避免同时在多端编辑同一方案。

## 接口与安全边界

- 原生 Java Views，无 AndroidX、Kotlin、WebUI Root JS 桥；高级面板单独使用 WebView。
- `ModuleClient` 只执行固定命令白名单。SSID 通过标准 Base64 传输，不拼接进 Shell 源码。
- 已授权的 Root 客户端通过本地 Unix socket 获取现有用户的 10 分钟会话。socket 验证 UID 0；HTTP 不提供会话签发入口。不会向 App 返回密码或签名密钥，也不创建或重置账户。
- 原生 API 客户端仅访问固定 `127.0.0.1:2023`，禁用 HTTP 代理和重定向；会话只保存在内存。GET 的认证失效可更新会话重试一次，修改请求不自动重发。
- 高级 WebView 仅允许同一本机地址，不暴露 JavaScript 原生接口，禁止文件／内容访问。其短期会话通过本机页面引导，退出时清理；停留超过会话有效期可返回后重新打开。
- 不申请 VPN、存储或应用列表权限，不提供外部导出的服务或 Provider；Android 云备份关闭。日志只在手机显示，未添加遥测与自动上传。
- 不直接修改 SQLite、节点文件、订阅文件或运行时拓扑，配置变更由模块接口执行。

## 构建与签名

需要 Python 3.10+、JDK 17、Android SDK Platform 35 和 Build Tools 35.0.0。可离线构建，不依赖 Gradle 或第三方 Maven 库：

```powershell
$env:ANDROID_HOME = 'C:\Android\sdk'
python android/manager/build.py
```

输出 `android/dist/DaedNext-Manager-v0.1.12.apk`，版本名从 Manifest 读取。首次构建在 gitignored 的 `android/private/` 下创建本地 PKCS12 密钥和元数据，后续构建沿用同一身份。**请单独安全备份该目录中的签名材料**；缺失原密钥时不能覆盖更新既有 App。不要把密钥、密码或设备数据提交到 GitHub。

运行 `python android/manager/test-text.py` 可检查多行条件、引号、注释、片段编辑与规则排序的保留行为；CI 同时执行这些纯 Java 检查及原生 App 编译。

发布签名证书 SHA256：`e2d6b055b318f5a647ba81f2fdfeecabca7442af393460f13fb21310c5af3312`。

CI 使用以下命令编译和对齐 APK，不读取或生成签名密钥：

```sh
python android/manager/build.py --unsigned
```

将已签名 APK 放入 `android/module/manager/DaedNext-Manager.apk` 后重新打包模块。运行时恢复工具会从锁定的 Release 取回 APK；修改 App 源码后应重新构建，不能用旧 APK 替代新代码。Release 发布模块 ZIP 和独立 APK 两个附件；ZIP 内也包含同一 APK，不发布 SHA256 附件。

首页开关动画默认 1.25 秒，失败确认回退默认 0.55 秒，遵循系统动画设置。请求与动画并行，不延迟后端操作；等待确认及动画期间阻止重复切换。界面文字以模块实际状态为准，黑名单 Wi-Fi 仍显示自动直连。关闭系统动画时直接更新；离开前台或视图脱离窗口时停止动画，静止状态没有循环帧。B 版素材来源与提示词见 [ARTWORK.md](ARTWORK.md)。

首次导入节点后须建立节点、群组、路由关联，操作见 [首次代理配置](../docs/FIRST-PROXY.md)。

开发版 alpha9 统一 KernelSU／Magisk／APatch 安装和服务脚本，仅允许 eBPF；目前实机验证仍限 KernelSU。其他管理器的隔离脚本检查不等于真机兼容认证，见 [适配说明](../docs/DEVICE-ADAPTER.md)。
